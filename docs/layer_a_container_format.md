# AEGIS — формат каскадного контейнера (СЛОЙ A) v1

> Контракт формата между Android-клиентом (`aegis-client`) и сервером (`aegis-server`),
> §0 / §4 / §5 технического задания. Этот документ — единый источник истины по байтовому
> формату контейнера слоя A. Клиентская реализация: `rust/aegis-core/src/cascade.rs`.

## 1. Назначение

Слой A — дополнительный, независимый от Signal (слой B) слой шифрования каждого
сообщения. Это **каскад из четырёх независимых AEAD** (шифрование по порядку,
вложенное), на четырёх независимых 256-битных ключах:

```
plaintext
  → XChaCha20-Poly1305   (K1)   AEAD, nonce 24 байта
  → AES-256-GCM          (K2)   AEAD, nonce 12 байт
  → Camellia-256 / EAX   (K3)   AEAD, nonce 16 байт
  → Twofish-256  / EAX   (K4)   AEAD, nonce 16 байт
  = контейнер (шифртекст)
```

Расшифровка — строго в обратном порядке (Twofish → Camellia → AES → XChaCha20).
При провале AEAD-тега **любого** слоя расшифровка немедленно прекращается.

> **Замена Serpent-256 → Camellia-256.** Исходный план (§5) называл третьим шифром
> Serpent-256. Аудированный крейт RustCrypto `serpent` во всех версиях принимает
> только 128-битный ключ (`KeySize = U16`), поэтому настоящий Serpent-256 через
> RustCrypto недостижим. Заменён на Camellia-256 (RFC 3713 / ISO-IEC 18033-3 /
> NESSIE / CRYPTREC) — 256-бит ключ, отдельное от AES/Twofish семейство, что
> сохраняет идею каскада «4×256 бит независимых слоёв». Решение согласовано с
> владельцем и учитывается версией формата.

## 2. Байтовый layout контейнера

```
+--------+---------+-----------------------------------------------------------+
| offset | размер  | поле                                                      |
+--------+---------+-----------------------------------------------------------+
|   0    |   4     | MAGIC = ASCII "AGSC" (0x41 0x47 0x53 0x43)                 |
|   4    |   1     | VERSION = 0x01                                            |
|   5    |  16     | nonce4 (Twofish-256/EAX)                                  |
|  21    |  ...    | ct4 = EAX_Twofish( key=K4, nonce=nonce4, msg=blob3, aad ) |
+--------+---------+-----------------------------------------------------------+

где blob3 = nonce3(16) || ct3,  ct3 = EAX_Camellia(K3, nonce3, blob2, aad)
    blob2 = nonce2(12) || ct2,  ct2 = AES-256-GCM(K2, nonce2, blob1, aad)
    blob1 = nonce1(24) || ct1,  ct1 = XChaCha20-Poly1305(K1, nonce1, plaintext, aad)
```

Каждый `ctN` включает 16-байтовый AEAD-тег (конкатенирован в конце шифртекста,
как принято в RustCrypto AEAD). Nonce каждого слоя — **случайный** (ОС-ГСЧ),
генерируется на каждое сообщение и никогда не переиспользуется.

### AAD (associated data)

На **каждом** слое AEAD-аутентифицируется значение:

```
effective_aad = MAGIC(4) || VERSION(1) || user_aad
```

`user_aad` задаёт вызывающий (например, метаданные пакета). Заголовок
(`MAGIC||VERSION`) входит в AAD всех слоёв, поэтому подмена версии/магии ломает
проверку тега (защита от downgrade). Между слоями данные **не сжимаются** (риск
CRIME, §4).

## 3. Вывод ключей K1..K4

Ключи независимы, по 256 бит, выводятся из общего секрета контейнера через
HKDF-SHA512 с **разделением доменов** (разные `info`-метки):

```
salt = "AEGIS/cascade/v1"
Kn   = HKDF-SHA512-Expand( PRK = HKDF-Extract(salt, container_secret), info = INFO_Kn, L = 32 )

INFO_K1 = "aegis/cascade/v1/k1-xchacha20"
INFO_K2 = "aegis/cascade/v1/k2-aes256"
INFO_K3 = "aegis/cascade/v1/k3-camellia256"
INFO_K4 = "aegis/cascade/v1/k4-twofish256"
```

`container_secret` — это:
- **PSK**, обменянный строго вручную / вне сети (QR/мнемоника/NFC, §6.2), ЛИБО
- выход **Argon2id** из парольной/мнемонической фразы (высокие параметры, §5).

Метки `INFO_Kn` совпадают с `CascadeSpec.hkdfInfoLabels` (Kotlin) и константами
`INFO_K*` (Rust) — единый контракт.

## 4. Роль сервера (zero-trust, §7.6)

`aegis-server` **никогда** не расшифровывает контейнер слоя A и не владеет
`container_secret` (тот в сеть не попадает). Для сервера контейнер — **непрозрачные
байты**. Обязательства сервера:

- Транспортировать контейнер как opaque BLOB (внутри слоя B / Signal-конверта);
- Не зависеть от внутренней структуры (кроме факта, что это бинарный BLOB);
- Не логировать содержимое (§7.6).

Версия (`VERSION`) в заголовке позволит согласованно эволюционировать формат;
при изменении набора шифров/схемы KDF версия инкрементируется в обоих репозиториях.

## 5. Тестовые гарантии (клиент)

`rust/aegis-core/src/cascade.rs` покрыт тестами: roundtrip каждого слоя и всего
каскада, провал при подмене тега на любом слое, независимость/детерминизм ключей,
провал при неверном секрете/AAD/заголовке, путь вывода ключа из фразы (Argon2id).
