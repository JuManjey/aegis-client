# Политика безопасности AEGIS (Security Policy)

AEGIS — защищённый мессенджер с моделью угроз «нулевого доверия» (zero-trust) ко
всему: к сети, провайдеру, транспорту и даже к собственному серверу (§0, §7.6
технического задания). Безопасность — центральное свойство продукта, поэтому мы
серьёзно относимся к любым сообщениям об уязвимостях.

Этот документ относится к **обоим репозиториям** продукта: `aegis-client`
(Android-клиент) и `aegis-server` (сервер-релей).

---

## Ответственное раскрытие (coordinated disclosure)

**Пожалуйста, НЕ создавайте публичный issue для уязвимостей.**

Сообщайте приватно:

- Приватный отчёт через GitHub: вкладка **Security → Report a vulnerability**
  (GitHub Security Advisories) в соответствующем репозитории.

Если вы разворачиваете собственную копию AEGIS, сообщайте об уязвимостях в
своём развёртывании его администратору; уязвимости самого кода — сюда.

Что включить в отчёт:

- Затронутый компонент (клиент/сервер), версия/коммит.
- Тип уязвимости и оценка воздействия (что компрометируется, при каких условиях).
- Шаги воспроизведения / PoC.
- Предлагаемое исправление (по желанию).

### Наши обязательства

| Этап | Срок (цель) |
|------|-------------|
| Подтверждение получения | ≤ 72 часа |
| Первичная оценка/триаж | ≤ 7 дней |
| План исправления | ≤ 30 дней (зависит от сложности) |
| Публичное раскрытие | по согласованию, обычно после выпуска фикса |

Мы соблюдаем принцип **safe harbor**: добросовестное исследование в рамках этой
политики не повлечёт с нашей стороны юридических претензий.

## Область (scope)

В приоритете — нарушения криптографических гарантий и модели угроз:

- Обход E2EE (слой B, libsignal/Double Ratchet) или слоя A (каскадный контейнер).
- Утечка plaintext, ключей (identity, PSK, ключ SQLCipher) или метаданных
  «кто-кому» на сервере/в сети.
- Обход анонимности транспорта (деанонимизация через Tor/PT, утечка IP).
- Обход `FLAG_SECURE`, экстренной очистки (crypto-shredding), duress-режима,
  автоблокировки, верификации отпечатка (§14.3).
- Уязвимости в обмене PSK вне сети, переносе аккаунта (§7.1.2), вложениях (§14.4).
- Нарушения zero-trust на сервере (сервер видит больше, чем должен, — §7.6).

Вне немедленного scope (но всё равно сообщайте): проблемы сторонних
аудированных библиотек (libsignal, Arti, RustCrypto, coturn) — их эскалируем
апстриму; уязвимости, требующие физического доступа к разблокированному
устройству с активной сессией.

## Криптографические принципы (что мы НЕ делаем)

- **Не изобретаем свою криптографию** (§1) — только аудированные библиотеки:
  libsignal (Signal Protocol), RustCrypto (каскад слоя A), Arti (Tor),
  официальные PT Tor Project. Свои реализации примитивов — недопустимы.
- **Encrypt-then-encrypt**, только AEAD на каждом слое, без сжатия между слоями
  (анти-CRIME) — см. `docs/layer_a_container_format.md` и техническое задание §4–5.
- **Безопасно по умолчанию** (пресет «Параноик», §8); ослабление — только явным
  осознанным действием пользователя.

Полная модель угроз: [`docs/threat-model.md`](docs/threat-model.md).
Область и материалы для аудита: [`docs/audit.md`](docs/audit.md).

## Проверяемость (verifiability)

- **Открытый код** (GPL-3.0-or-later, см. `LICENSE`).
- **Воспроизводимые сборки** — [`docs/reproducible-builds.md`](docs/reproducible-builds.md):
  independent-ребилдер может доказать, что распространяемый APK собран из этого кода.
- **SBOM / инвентарь зависимостей** — `docs/sbom/` (генерируется `scripts/generate-sbom.sh`).
- **Проверка подписи/контрольной суммы** скачанного APK — `README.md`, раздел «Публикация и проверка контрольных сумм».
