AEGIS — мессенджер для Android по принципу «нулевого доверия»: он не доверяет
ни сети, ни провайдеру, ни транспортному каналу, ни даже собственному серверу.

Мы соединяем индустриальный стандарт — Signal Protocol (PQXDH + Double Ratchet) —
со вторым слоем шифрования на ключе, который не проходит через сервер, и
по умолчанию маршрутизируем весь трафик через Tor. Свою криптографию мы не
изобретаем: все примитивы взяты из аудированных библиотек.

Ключевые свойства
• Многослойное шифрование (defense-in-depth). Каждое сообщение упаковывается в
  каскадный контейнер (XChaCha20-Poly1305 → AES-256-GCM → Camellia-256 →
  Twofish-256) на ключе, который не передаётся через сервер, а затем ещё раз
  запечатывается Double Ratchet. Взлом одного из шифров или слоя Signal не
  раскрывает содержимое. Ключ контейнера (PSK) берегите как главный секрет: в
  текущей версии тот, кто его узнал, может незаметно подключиться к переписке
  как ещё одно устройство собеседника.
• Tor по умолчанию. Весь трафик клиента, включая звонки, идёт через встроенный
  Tor (Arti); релей публикуется как Onion Service v3. Мосты и pluggable
  transports (obfs4, snowflake, meek) помогают обходить цензуру. Tor можно
  выключить ради скорости — тогда приложение честно предупредит, что сервер и
  собеседник увидят ваш IP; шифрование при этом не меняется.
• Без номера телефона. Аккаунт — это криптографическая пара ключей; вход по
  логину/паролю или автосозданной личности. Восстановление — по мнемонической
  фразе (возвращается аккаунт, но не переписка).
• Добавление контактов. Лично — обменом QR-кодами: ключ контейнера (PSK) не
  проходит через сервер, поэтому даже полностью враждебный сервер не проведёт
  MITM. Удалённо — по адресу контакта: общий секрет выводится из подписанного
  рукопожатия. Обмен мнемоникой и по NFC пока не работает.
• Защита на устройстве. База SQLCipher, ключи в Android Keystore / StrongBox,
  вход по паролю (Argon2id) или биометрии, запрет скриншотов (FLAG_SECURE) на
  всех экранах, кроме экрана сканера QR, без облачных бэкапов.
• Шифрованные звонки. Голос и видео поверх WebRTC/DTLS-SRTP с дополнительным
  кадровым слоем AES-128-GCM на ключах из Signal-канала и PSK и кодом сверки
  (SAS); при включённом Tor медиа тоже идёт через Tor.
• Экстренная очистка. Мгновенное крипто-уничтожение всех ключей плюс
  best-effort перезапись свободного места (не более 4 ГиБ); опциональный
  пароль-обманка (duress), который стирает данные вместо входа.
• Автоудаление. Сервер хранит сообщения не дольше 7 дней; на устройстве можно
  выбрать меньший срок.
• Безопасные настройки по умолчанию (профиль «Параноик»); отчёты о прочтении,
  «печатает» и онлайн-статус включены, но отключаются в настройках приватности.

Честные компромиссы
Обмен ключами вне сети добавляет трение и требует личного контакта. Статичный
PSK сам по себе не даёт forward secrecy (его даёт слой Signal). Сервер не видит
содержимого, но метаданные от него защищены не полностью: оператор релея может
связать ящики одного пользователя и восстановить, кто с кем переписывается (без
имён), а тип и размер сообщений ему видны. Отзыв привязанного устройства пока
ненадёжен. Больше слоёв — больше поверхность ошибок, поэтому независимый аудит
обязателен; проект полностью открыт (GPL-3.0-or-later) и имеет инструменты
воспроизводимой сборки, чтобы этот аудит был проверяемым.

Статус: это сборка фазы 2. Внешний аудит безопасности ещё не проводился. Не
полагайтесь на приложение в задачах с высоким риском до завершения аудита.
