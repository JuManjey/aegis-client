# AEGIS — Android-клиент защищённого мессенджера

> **ВНИМАНИЕ: проект не завершён.**
>
> AEGIS — рабочий, но **не законченный** прототип. Основные функции реализованы и
> работают, однако часть заявленного не доделана, есть известные ошибки и
> ограничения — они честно перечислены в разделе
> [«Известные ограничения»](#известные-ограничения).
>
> - Независимый аудит безопасности **не проводился**. Собственные композиции
>   криптографических примитивов (каскад слоя A, PSK-обёртка, рукопожатие RCH,
>   вывод ключей звонка) ещё ждут независимого криптографического ревью.
> - Протокол и форматы данных могут меняться без обратной совместимости.
> - Не полагайтесь на AEGIS там, где от защиты переписки зависят жизнь, свобода
>   или безопасность людей.
>
> Готовых сборок и общего сервера нет. Чтобы пользоваться мессенджером, нужно
> развернуть свой сервер (репозиторий **`aegis-server`**) и собрать APK по этой
> инструкции.

AEGIS — мессенджер для Android с многослойным шифрованием, встроенным Tor и
аккаунтом без привязки к номеру телефона или e-mail. Этот репозиторий —
**клиент** (Android-приложение). Серверная часть (релей, через который клиенты
обмениваются зашифрованными сообщениями) — в репозитории **`aegis-server`**.

Лицензия — **GPL-3.0-or-later** (см. [`LICENSE`](LICENSE)).

## Статус проекта

Версия приложения — **0.4.2** (`versionCode 6`).

### Что реализовано и работает

- **Аккаунт без телефона.** Аккаунт — это пара криптографических ключей.
  Пароль защищается Argon2id; восстановление — по фразе из слов (BIP-39).
  Фраза восстанавливает аккаунт, но **не** переписку.
- **Шифрование сообщений — два независимых слоя:**
  - слой B — протокол Signal на официальной libsignal (X3DH/PQXDH + Double Ratchet);
  - слой A — каскад из четырёх шифров XChaCha20-Poly1305 → AES-256-GCM →
    Camellia-256 → Twofish-256 на отдельном общем секрете собеседников (PSK),
    который передаётся лично, вне сети.
- **Встроенный Tor (Arti)**, включён по умолчанию: onion-адрес сервера, мосты и
  pluggable transports (obfs4, snowflake, meek) для обхода блокировок.
- **Режим без Tor** (только явным выбором пользователя, с предупреждением): HTTPS
  к тому же серверу. Шифрование от режима не зависит.
- **Добавление контактов:** при личной встрече по QR-коду (самый строгий способ)
  или удалённо — по адресу вида `aegis:1:…`.
- **Голосовые и видеозвонки** — WebRTC (DTLS-SRTP) плюс дополнительное шифрование
  кадров AES-128-GCM на ключах из Signal+PSK, сверка кода безопасности (SAS).
  Медиа через TURN вашего сервера (в режиме Tor — через onion).
- **Хранилище:** SQLCipher, ключи в Android Keystore/StrongBox.
- **Защита на устройстве:** экстренная очистка (crypto-shredding + перезапись
  свободного места), пароль-обманка (duress), биометрия, автоблокировка,
  запрет снимков экрана (`FLAG_SECURE`), автоудаление сообщений (до 7 суток).
- **Вложения и голосовые сообщения**, отчёты о прочтении, «печатает…»,
  чёрный список, уведомления.
- **Несколько устройств** на одном аккаунте и перенос аккаунта на новое устройство.
- **Оформление:** тёмная/светлая тема, русский и английский языки, обои чатов,
  маскировка иконки приложения.

### Что не доделано (кратко)

- Защита метаданных от **собственного** сервера неполная: оператор сервера может
  восстановить псевдонимный граф «кто с кем общается».
- Не работают: обмен PSK фразой из слов и приём PSK по NFC, публикация `@ника`.
- Отзыв привязанного устройства ненадёжен.
- Пины сертификатов для HTTPS и авто-обновление адреса сервера по умолчанию
  выключены (их можно включить при сборке — см. ниже).

Подробно — в разделе [«Известные ограничения»](#известные-ограничения).

## Как устроена система

Система состоит из двух частей:

| Часть | Репозиторий | Что делает |
|---|---|---|
| Клиент | `aegis-client` (этот) | Android-приложение: ключи, шифрование, интерфейс, встроенный Tor |
| Сервер | `aegis-server` | Релей: хранит и передаёт **только шифртекст**, выдаёт креды TURN для звонков |

```
  Телефон A                        Ваш сервер (aegis-server)                       Телефон B
┌───────────┐   Tor (onion)   ┌──────────────────────────────────┐   Tor (onion)   ┌───────────┐
│   AEGIS   │ ──────────────► │ tor ─► relay (очереди, SQLite)   │ ◄────────────── │   AEGIS   │
│  клиент   │                 │    └─► coturn (TURN для звонков)  │                 │  клиент   │
└───────────┘                 └──────────────────────────────────┘                 └───────────┘
```

Как проходит сообщение:

1. Текст шифруется слоем B (Signal), затем каскадом слоя A на общем секрете
   (PSK), который собеседники передали друг другу лично.
2. Готовый шифртекст через встроенный Tor отправляется в анонимный «почтовый
   ящик» на сервере. Адрес ящика выводится из PSK, сервер не знает, чей он.
3. Получатель забирает конверт из ящика (тоже через Tor) и расшифровывает.

Важно знать заранее:

- **Push-сервисов (Google FCM и т. п.) нет.** Сообщения и звонки приходят по
  постоянному соединению с сервером, поэтому приложению нужно разрешить работу в
  фоне (см. [Шаг 7](#шаг-7-первый-запуск)).
- **Собеседники должны быть на одном сервере.** Приложение работает с одним
  адресом релея, федерации между серверами нет.
- **Сервер никогда не видит текст сообщений и ключи.** Но метаданные от него
  защищены не полностью (см. ограничения).
- У приложения два режима сети: **Tor ВКЛ** (по умолчанию: всё через onion, при
  недоступном Tor сообщения не уходят мимо него) и **Tor ВЫКЛ** (HTTPS напрямую к
  тому же серверу; сервер и собеседник по звонку видят ваш IP). Режим без Tor
  работает, только если на сервере включён клирнет-профиль.

## Шаг 1. Подготовка окружения

Команды ниже — для **Ubuntu 22.04/24.04** (Debian аналогично). Отличия для macOS
приведены отдельно.

### 1.1. Системные пакеты

```bash
sudo apt-get update
sudo apt-get install -y git curl unzip zip build-essential pkg-config \
    protobuf-compiler openjdk-17-jdk python3
```

- `build-essential` — системный компилятор C: Rust нужен линкер для сборочных
  скриптов зависимостей.
- `protobuf-compiler` (`protoc`) — без него не соберётся слой B (libsignal).
- `openjdk-17-jdk` — JDK для Gradle. Если ставите Android Studio, можно вместо
  него использовать встроенный в неё JBR.

**macOS:** установите Xcode Command Line Tools (`xcode-select --install`) и
[Homebrew](https://brew.sh), затем `brew install protobuf go git`.

### 1.2. Android SDK, NDK и CMake

**Вариант А — через Android Studio (проще).**

1. Установите [Android Studio](https://developer.android.com/studio).
2. Откройте **Settings → Languages & Frameworks → Android SDK**
   (на macOS — **Android Studio → Settings…**).
3. Вкладка **SDK Platforms**: отметьте **Android 16 (API 36)**.
4. Вкладка **SDK Tools**: включите **Show Package Details** и отметьте:
   - **Android SDK Build-Tools** — 36.0.0 (или новее);
   - **NDK (Side by side)** — ровно **30.0.15729638**;
   - **CMake** — **3.22.1**;
   - **Android SDK Platform-Tools**;
   - **Android SDK Command-line Tools (latest)**.
5. Нажмите **Apply** и дождитесь загрузки.

SDK по умолчанию ставится в `~/Android/Sdk` (Linux) или `~/Library/Android/sdk` (macOS).

**Вариант Б — только командная строка (без Android Studio).**

1. Скачайте архив **«Command line tools only»** для вашей ОС со страницы
   <https://developer.android.com/studio#command-line-tools-only>.
2. Распакуйте и установите компоненты:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
mkdir -p "$ANDROID_HOME/cmdline-tools"
unzip ~/Downloads/commandlinetools-linux-*_latest.zip -d "$ANDROID_HOME/cmdline-tools"
mv "$ANDROID_HOME/cmdline-tools/cmdline-tools" "$ANDROID_HOME/cmdline-tools/latest"
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" \
           "ndk;30.0.15729638" "cmake;3.22.1"
```

Если Gradle попросит другую версию build-tools или платформы, он скачает её сам
(лицензии уже приняты).

### 1.3. Rust и cargo-ndk

```bash
# rustup (менеджер версий Rust)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"

# Точная версия, на которой закреплён проект, и таргеты Android
rustup toolchain install 1.97.0 --profile minimal
rustup target add --toolchain 1.97.0 \
    aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android

# Обёртка cargo для сборки под Android NDK
cargo install cargo-ndk --locked
```

Файл `rust/aegis-core/rust-toolchain.toml` заставляет cargo в этом каталоге
использовать именно Rust 1.97.0 — даже если по умолчанию у вас другая версия.

### 1.4. Go (для мостов Tor)

Go нужен, чтобы собрать мосты obfs4/meek (lyrebird) и snowflake — без них Tor не
сможет обходить блокировки. Подойдёт любая версия **1.21+**: при сборке Go сам
скачает закреплённую версию go1.26.5.

```bash
sudo apt-get install -y golang-go     # или архив с https://go.dev/dl/
go version
```

Без Go приложение тоже соберётся, но **без мостов**: в сетях, где Tor
заблокирован, оно не подключится.

### 1.5. Переменные окружения

Добавьте в `~/.bashrc` (или `~/.zshrc` на macOS) и перезапустите терминал:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"                  # macOS: $HOME/Library/Android/sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/30.0.15729638"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$HOME/.cargo/bin:$PATH"
# Если используете JDK из Android Studio вместо системного:
# export JAVA_HOME="$HOME/android-studio/jbr"            # macOS: "/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

### 1.6. Проверка окружения

```bash
java -version                 # 17 или новее
cargo --version               # любая; в rust/aegis-core будет 1.97.0
cargo ndk --version           # cargo-ndk 4.x
protoc --version              # libprotoc 3.x или новее
go version                    # go1.21 или новее
ls "$ANDROID_NDK_HOME"        # каталог NDK 30.0.15729638 существует
```

Если какая-то команда не находится — вернитесь к соответствующему пункту.
Нехватка любого из инструментов **не остановит** сборку, но приложение
соберётся урезанным (подробнее — в [Шаге 5](#шаг-5-проверка-сборки)).

## Шаг 3. Адрес вашего сервера

Приложение подключается только к тому серверу, адрес которого ему известен. В
публичном коде адреса **пустые** — каждый, кто разворачивает AEGIS, указывает
свой сервер.

1. Разверните сервер по инструкции из репозитория `aegis-server` и узнайте его
   onion-адрес (команда выполняется на сервере):

   ```bash
   docker compose exec -T tor cat /var/lib/tor/aegis/hostname
   ```

2. Выберите способ передать адрес в сборку:

   **а) в `gradle.properties` проекта** — адрес попадёт в git вашей копии
   репозитория:

   ```properties
   aegis.defaultRelayOnion=<56 символов>.onion
   # Только если на сервере включён клирнет-профиль (режим «Tor ВЫКЛ»):
   aegis.defaultRelayHttps=https://relay.example.com
   ```

   **б) в `~/.gradle/gradle.properties`** (личный файл Gradle, вне репозитория) —
   те же строки; так адрес вашего сервера не окажется в публичном git. Значения
   из этого файла имеют приоритет над `gradle.properties` проекта.

   **в) флагами при сборке:**

   ```bash
   ./gradlew :app:assembleDebug \
       -Paegis.defaultRelayOnion=<56 символов>.onion \
       -Paegis.defaultRelayHttps=https://relay.example.com
   ```

   **г) не задавать вовсе** — тогда после установки приложение покажет «Адрес
   onion-релея не задан», и адрес нужно ввести вручную: **Настройки → Сеть и Tor
   → Адрес релея**.

Ограничения формата: onion — только v3 (56 символов + `.onion`); HTTPS —
строго `https://хост[:порт]` без пути (адрес с `http://` или путём остановит
сборку с ошибкой).

> Onion-адрес — публичная информация (как доменное имя): его знание не даёт
> доступа к переписке. Но если не хотите, чтобы ваш сервер был известен всем,
> используйте способ «б» или «в».

## Шаг 4. Сборка APK

Первую сборку лучше запускать **из терминала**: Android Studio, запущенная из
меню рабочего стола, может не видеть `cargo`, `protoc` и `go` в `PATH`.

```bash
./gradlew :app:assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

Что происходит при сборке (по порядку):

1. `:crypto:cargoNdkBuild` — компилирует нативное криптоядро `libaegis_core.so`
   (Rust: слой A, Signal, Tor/Arti) для каждой ABI. Это самый долгий этап.
2. `:app:buildPluggableTransports` — компилирует мосты `liblyrebird.so` и
   `libsnowflake.so` (Go; исходники скачиваются с `gitlab.torproject.org`).
3. CMake — собирает `libaegis_frame.so` (шифрование кадров звонков, C++).
4. Компиляция Kotlin и упаковка APK.

По умолчанию сборка идёт сразу для двух ABI — `arm64-v8a` (телефоны) и `x86_64`
(эмулятор), см. `aegis.abiFilters` в `gradle.properties`. Если нужен только
телефон, сборка будет почти вдвое быстрее, а APK меньше:

```bash
./gradlew :app:assembleDebug -Paegis.abiFilters=arm64-v8a
```

**Через Android Studio:** **File → Open** → папка `aegis-client` → дождитесь
Gradle Sync → **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

## Шаг 5. Проверка сборки

Нативные части собираются в режиме «best-effort»: если какого-то инструмента нет
или компиляция упала, Gradle **не останавливается**, а собирает APK без этой
части. Такой APK запустится, но будет неполноценным. Поэтому после сборки
обязательно проверьте три вещи.

**1. Журнал сборки.** Должна быть строка:

```
[aegis] cargo-ndk build, фичи: signal,tor
```

и **не** должно быть предупреждений:

| Предупреждение | Что это значит |
|---|---|
| `cargoNdkBuild пропущен …` | нативное ядро не собрано вовсе — нельзя создать аккаунт |
| `Слой B (signal) пропущен: protoc не найден` | нет `protoc` — нет шифрования Signal |
| `Нативная сборка удалась с усечённым набором фич` | Signal или Tor не скомпилировались — см. ошибку выше в журнале |
| `buildPluggableTransports пропущен …` | нет Go или NDK — нет мостов |
| `Сборка PT завершилась с кодом …` | мосты не собрались (часто — нет доступа к `gitlab.torproject.org`) |

**2. Содержимое APK.**

```bash
unzip -l app/build/outputs/apk/debug/app-debug.apk | grep '\.so$'
```

Для каждой ABI (`lib/arm64-v8a/`, `lib/x86_64/`) должны быть:

| Библиотека | Назначение |
|---|---|
| `libaegis_core.so` | криптоядро: слой A, Signal, Tor (Rust) |
| `libaegis_frame.so` | шифрование кадров звонков (C++) |
| `liblyrebird.so` | мосты obfs4 и meek (Go) |
| `libsnowflake.so` | мост snowflake (Go) |
| `libsqlcipher.so` | зашифрованная база данных |
| `libjingle_peerconnection_so.so` | WebRTC (звонки) |
| `libandroidx.graphics.path.so` | служебная библиотека Compose |

**3. В самом приложении:** **Настройки → Крипто-ядро (диагностика)** должна
показать строку с `+signal+tor`:

```
Нативное крипто-ядро: aegis-core 0.1.0 (phase-2: account+cascade+psk+signal+tor)
```

## Шаг 6. Установка на телефон

**По USB (adb):**

   появится раздел **Для разработчиков** → включить **Отладку по USB**.

./gradlew :app:installDebug     # или: adb install -r app/build/outputs/apk/debug/app-debug.apk

Особенности debug-сборки:

- красный баннер «Отладочная сборка» на экране;
- к ней можно подключить отладчик, поэтому **раздавать debug-сборку
  пользователям нельзя** — для них собирайте подписанный release (раздел
  [«Подпись»](#подпись)).

## Шаг 7. Первый запуск

1. **Аккаунт.** На первом экране выберите:
   - **Создать аккаунт** — логин и пароль (пароль защищается Argon2id);
   - **Быстрое создание (без пароля)**;
   - **Восстановить по фразе** — если аккаунт уже был.

   Запишите фразу восстановления на бумагу и храните офлайн. Она восстанавливает
   аккаунт, но **не** старую переписку. Перед созданием нового аккаунта приложение
   полностью очищает данные на устройстве.

2. **Сеть.** Откройте **Настройки → Сеть и Tor**:
   - убедитесь, что в поле **Адрес релея** стоит onion-адрес вашего сервера
     (если не вшили его при сборке — введите вручную);
   - нажмите **Проверить достижимость через Tor**. Первое подключение к Tor
     может занять минуту и больше;
   - если в вашей сети Tor заблокирован — включите **Мосты / pluggable
     transports**. Встроенные строки мостов со временем устаревают; свежие
     можно получить на <https://bridges.torproject.org>.

3. **Работа в фоне.** Приложение предложит выдать разрешения — согласитесь:
   уведомления, работа в фоне без оптимизации батареи, полноэкранный входящий
   звонок (Android 14+). Без них свёрнутое приложение замораживается системой:
   звонки не звонят, сообщения приходят с опозданием. Проверить всё можно в
   **Настройки → Приём в фоне**.

4. **Контакты.** Откройте **Добавить контакт**:
   - **Личный обмен (QR/NFC)** — самый строгий способ. Оба собеседника рядом:
     каждый сначала открывает свой QR (**Показать мой ключ**), затем сканирует QR
     другого (**Сканировать QR собеседника**). Сверьте вслух отпечаток ключа.
     Не позволяйте снимать экраны во время обмена: утечка этого секрета равна
     компрометации переписки;
   - **По адресу или нику** — скопируйте **Мой адрес** (`aegis:1:…`), передайте
     собеседнику по надёжному каналу; он вставляет адрес и отправляет заявку, вы
     принимаете её в разделе **Заявки в контакты**. Поиск по `@нику` в версии
     0.4.2 не работает (см. ограничения).

   Оба собеседника должны быть подключены к **одному** серверу.

5. **Звонки** работают, только если на сервере настроен TURN (см. README
   `aegis-server`, раздел «TURN для звонков»). В начале разговора сверьте с
   собеседником код безопасности (SAS) на экране звонка.

## Подпись

Android ставит обновление поверх установленного приложения, только если оба APK
подписаны **одним и тем же ключом**.

### Debug-сборка

По умолчанию debug-APK подписывается стандартным ключом Android Studio с вашего
компьютера (`~/.android/debug.keystore`, создаётся автоматически). Сборки с
разных компьютеров при этом подписаны **разными** ключами и не ставятся друг
поверх друга (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`).

Если вы собираете на нескольких машинах, создайте **общий debug-ключ** один раз
и скопируйте его на остальные машины (не через публичный репозиторий —
`*.jks` в `.gitignore`):

```bash
mkdir -p app/signing
keytool -genkeypair -v \
  -keystore app/signing/aegis-debug.jks -alias aegis-debug \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass android -keypass android \
  -dname "CN=AEGIS Debug"
```

Если файл `app/signing/aegis-debug.jks` существует, сборка использует его
автоматически (пароль и алиас — ровно как в команде выше). Он подписывает только
debug-пакет `com.aegis.messenger.debug`.

### Release-сборка

1. **Создайте релизный ключ** (один раз, храните вне репозитория и сделайте
   резервную копию):

   ```bash
   keytool -genkeypair -v \
     -keystore ~/aegis-release.jks -alias aegis \
     -keyalg RSA -keysize 4096 -validity 10000
   ```

   Потеряете ключ — не сможете выпускать обновления (пользователям придётся
   удалить приложение вместе с данными). Утечёт ключ — кто угодно сможет выпустить
   «обновление», которое телефон примет как ваше.

2. **Создайте `keystore.properties`** в корне проекта (файл в `.gitignore`):

   ```properties
   storeFile=/home/<пользователь>/aegis-release.jks
   storePassword=<пароль хранилища>
   keyAlias=aegis
   keyPassword=<пароль ключа>
   ```

   Относительный путь в `storeFile` считается от корня проекта.

3. **Соберите:**

   ```bash
   ./gradlew :app:assembleRelease   # → app/build/outputs/apk/release/app-release.apk
   ./gradlew :app:bundleRelease     # → app/build/outputs/bundle/release/app-release.aab (для Google Play)
   ```

   Без `keystore.properties` получится **неподписанный**
   `app-release-unsigned.apk` (Gradle предупредит об этом) — такой файл телефон
   не установит. Подписи debug-ключом у release нет намеренно.

4. **Проверьте подпись:**

   ```bash
   "$ANDROID_HOME"/build-tools/36.0.0/apksigner verify --print-certs \
       app/build/outputs/apk/release/app-release.apk
   ```

В release включены R8 (минификация и сокращение ресурсов, правила —
`app/proguard-rules.pro`). Пакет release-версии — `com.aegis.messenger`.

## Параметры сборки

Любой параметр задаётся в `gradle.properties`, в `~/.gradle/gradle.properties`
или флагом `-P<имя>=<значение>`.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `aegis.abiFilters` | `arm64-v8a,x86_64` | ABI через запятую (`arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`) |
| `aegis.defaultRelayOnion` | пусто | onion-адрес сервера «из коробки» |
| `aegis.defaultRelayHttps` | пусто | HTTPS-адрес того же сервера для режима «Tor ВЫКЛ» |
| `aegis.relayHttpsPins` | пусто | пины SPKI к HTTPS-адресу (см. [«Пины SPKI»](#пины-spki)) |
| `aegis.relayConfigPubkey` | пусто | ключ проверки подписанного конфига (см. [ниже](#подписанный-конфиг-релея)) |
| `aegis.buildRust` | `true` | собирать нативное криптоядро (Rust) |
| `aegis.signal` | `true` | включать слой B (libsignal; нужен `protoc`) |
| `aegis.tor` | `true` | включать встроенный Tor (Arti) |
| `aegis.buildPt` | `true` | собирать мосты obfs4/meek/snowflake (нужен Go) |
| `aegis.buildFrame` | `true` | собирать C++-модуль шифрования кадров звонков |

Переменные окружения: `ANDROID_NDK_HOME` (путь к NDK), `AEGIS_GO_TOOLCHAIN`
(версия Go для мостов, по умолчанию `go1.26.5`; `local` — использовать
установленный Go без скачивания).

Отключать `buildRust`, `signal` или `tor` имеет смысл только для быстрой проверки
Kotlin-кода: такое приложение не сможет полноценно работать.

## Пины SPKI

Только для режима «Tor ВЫКЛ» и только если на сервере включён клирнет-профиль.
Без пинов приложение проверяет HTTPS-сертификат сервера обычным системным
способом (цепочка доверия и имя хоста) — этого достаточно для большинства
случаев. Пины дополнительно привязывают приложение к конкретным ключам.

Пиньте ключи **корневых** сертификатов Let's Encrypt (обоих — ISRG Root X1 и X2),
а **не** сертификата сервера: сервер меняет свой ключ при каждом продлении
сертификата, и пин на него отрезал бы всех пользователей через пару месяцев.

```bash
for f in /etc/ssl/certs/ISRG_Root_X1.pem /etc/ssl/certs/ISRG_Root_X2.pem; do
  echo "sha256/$(openssl x509 -in "$f" -pubkey -noout \
    | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | openssl base64)"
done
```

Результат (у этих корней он постоянный):

```properties
aegis.relayHttpsPins=sha256/C5+lpZ7tcVwmwQIMcRtPbsQtWLABXhQzejna0wHFr8M=,sha256/diGVwiVYbubAI3RW4hB9xU8e/CH2GnkuvVFZE8zmgzI=
```

Пины без `aegis.defaultRelayHttps` или с опечаткой останавливают сборку с
ошибкой — так пиннинг не может молча выключиться. К адресу, введённому вручную в
приложении, пины не применяются.

## Подписанный конфиг релея

Необязательная функция: сервер раздаёт приложениям свой актуальный адрес
(`GET /v1/config`), и при смене адреса не нужно пересобирать APK. Документ с
адресами подписывается **офлайн-ключом** Ed25519; приложение проверяет подпись
публичным ключом, вшитым при сборке, поэтому даже взломанный сервер не сможет
подсунуть чужой адрес.

1. Сгенерируйте ключ инструментом `aegis-config-sign` из репозитория
   `aegis-server` (README сервера, раздел «Подписанный конфиг»). Закрытый ключ
   храните офлайн.
2. Вшейте **публичный** ключ (64 hex-символа) в сборку:

   ```properties
   aegis.relayConfigPubkey=<PUBLIC_KEY_HEX>
   ```

Без ключа функция выключена: приложение использует только вшитый или введённый
вручную адрес. Адреса, введённые вручную, авто-обновление не перезаписывает.

## Воспроизводимые сборки

Цель — чтобы любой мог собрать из этого кода APK, побайтно совпадающий с
опубликованным, и убедиться, что в нём нет ничего лишнего. Для этого закреплены
версии Rust (1.97.0), NDK, Gradle и всех зависимостей (`Cargo.lock`,
`gradle/libs.versions.toml`), исходники мостов, а из APK исключён
недетерминированный блок метаданных зависимостей.

```bash
scripts/verify-reproducible-build.sh                          # дважды собрать ядро (arm64-v8a) и сравнить SHA-256
AEGIS_ABIS="arm64-v8a x86_64" scripts/verify-reproducible-build.sh
AEGIS_VERIFY_APK=1 scripts/verify-reproducible-build.sh       # то же для неподписанного APK

# Сравнение подписанного APK с эталоном без учёта подписи:
pip install apksigcopier diffoscope
apksigcopier compare reference.apk rebuilt.apk --unsigned
```

Подробности и ограничения — [`docs/reproducible-builds.md`](docs/reproducible-builds.md).
Список зависимостей (SBOM) — [`docs/sbom/`](docs/sbom/), обновляется
`scripts/generate-sbom.sh`.

## Публикация и проверка контрольных сумм

Раздавая APK своим пользователям, публикуйте рядом контрольные суммы и, по
возможности, их GPG-подпись:

```bash
# SHA256SUMS для всех APK/AAB в каталоге (+ SHA256SUMS.asc, если есть GPG-ключ)
OUT_DIR=dist scripts/publish-checksums.sh app/build/outputs/apk/release
# Подпись конкретным ключом:
AEGIS_GPG_KEY=<id ключа> OUT_DIR=dist scripts/publish-checksums.sh app/build/outputs/apk/release
```

Пользователь проверяет скачанное так:

```bash
sha256sum -c SHA256SUMS
gpg --verify SHA256SUMS.asc SHA256SUMS
apksigner verify --print-certs app-release.apk   # сертификат должен совпадать с опубликованным
```

Каналы распространения:

- **Прямое скачивание** (сайт, onion, GitHub Releases) — с контрольными суммами.
- **F-Droid** — рецепт сборки из исходников и описания уже подготовлены:
  [`fdroid/`](fdroid/) и [`fastlane/metadata/android/`](fastlane/metadata/android).
  Известные сложности — в [`fdroid/README.md`](fdroid/README.md).
- **Google Play** — AAB (`bundleRelease`), политика приватности и декларация об
  использовании шифрования.

## CI на GitHub Actions

Workflow уже лежат в `.github/workflows/` и заработают после публикации репозитория:

| Файл | Когда | Что делает |
|---|---|---|
| `ci.yml` | push и pull request в `main` | формат, clippy и тесты криптоядра; debug-сборка Kotlin + C++ и JVM-тесты |
| `reproducible-build.yml` | теги `v*`, вручную, раз в неделю | двойная сборка ядра и сравнение SHA-256 |
| `release.yml` | теги `v*`, вручную | release-APK, `SHA256SUMS`, GPG-подпись, GitHub Release |

Для подписанного релиза задайте секреты репозитория (**Settings → Secrets and
variables → Actions**): `ANDROID_KEYSTORE_BASE64` (keystore в base64:
`base64 -w0 aegis-release.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`, а для подписи сумм — `GPG_PRIVATE_KEY` и `GPG_KEY_ID`.
Без секретов release-APK соберётся неподписанным.

`release.yml` не передаёт адрес сервера: если хотите вшить его в релиз, добавьте
в шаг «Assemble release APK» флаги `-Paegis.defaultRelayOnion=…` (например, из
переменных репозитория). Подробности — [`docs/ci.md`](docs/ci.md).

## Известные ограничения

По результатам аудита кода от 01.11.2026. Шифрование содержимого реализовано
полностью и на реальных библиотеках; ниже — где код пока не дотягивает до
заявленного. Полный список — [`docs/audit.md`](docs/audit.md) (§5), влияние на
гарантии — [`docs/threat-model.md`](docs/threat-model.md).

- **Метаданные от собственного сервера защищены не полностью.** Все запросы
  клиента идут через одну Tor-цепочку без изоляции потоков, по отдельному
  long-poll на каждый контакт к статичным ящикам — оператор сервера может связать
  ящики одного пользователя и восстановить псевдонимный граф «кто с кем». Внешний
  конверт — открытый JSON (тип трафика, `msgId`, номер устройства-отправителя),
  длина не выравнивается; фиктивный трафик сервер отличает от настоящего.
- **Утечка PSK равна компрометации переписки.** Канал `keyx` защищён только
  слоем A, и закрепление identity в нём обходится: знающий PSK может незаметно
  добавить «устройство» собеседника со своим ключом. Обе половины PSK видны на
  экранах одновременно — берегите обмен от съёмки.
- **Отзыв привязанного устройства ненадёжен:** отозванное устройство может снять
  отзыв повторным объявлением, а фраза восстановления, PSK и адреса ящиков при
  отзыве не меняются.
- **Не работают:** обмен PSK фразой из слов и приём PSK по NFC (по NFC работает
  только отдающая сторона), публикация `@ника` (клиент отправляет поле
  `ed25519Hex`, сервер ждёт `ed25519`).
- **Выключено по умолчанию:** пины SPKI для HTTPS и авто-обновление адреса
  сервера по подписанному конфигу (пустые `aegis.relayHttpsPins` и
  `aegis.relayConfigPubkey`).
- **Прочее:** EXIF из фото не удаляется; пакеты переноса и привязки устройства
  защищены Argon2id 64 МиБ / 3 / 1 при пароле от 8 символов; проверка
  «duress-пароль ≠ основной» не срабатывает; автоблокировка работает только на
  переднем плане; отчёты о прочтении, «печатает» и онлайн-статус включены по
  умолчанию даже в профиле «Параноик»; переключателя профилей безопасности в
  интерфейсе нет (настройки меняются по отдельности); в нативном ядре
  зафиксированы версии зависимостей с известными бюллетенями RustSec (rustls,
  rustls-webpki, zstd, libcrux-secrets).
- **Платформа:** бинарники мостов проверены как корректные для Android, но
  реальный обход блокировок в цензурируемой сети не проверялся; WebRTC
  подключается готовым Maven-артефактом, что мешает публикации в основном
  репозитории F-Droid.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `cargoNdkBuild пропущен: cargo-ndk не найден` | Установите `cargo install cargo-ndk --locked`; проверьте, что `~/.cargo/bin` есть в `PATH` |
| `cargoNdkBuild пропущен: NDK не найден` | Установите NDK **30.0.15729638**, задайте `ANDROID_NDK_HOME` или `sdk.dir` в `local.properties` |
| `Слой B (signal) пропущен: protoc не найден` | Установите `protobuf-compiler` (`brew install protobuf` на macOS). Android Studio, запущенная не из терминала, может не видеть `protoc` — соберите из терминала |
| `Нативная сборка удалась с усечённым набором фич` | Найдите выше в журнале первую ошибку `error:`. Частые причины: нет сети для git-зависимости libsignal; не хватает памяти — закройте лишнее или ограничьте параллельность: `CARGO_BUILD_JOBS=2 ./gradlew …` |
| `buildPluggableTransports пропущен: go не найден` | Установите Go 1.21+ (`/usr/local/go/bin` и `~/go/bin` ищутся автоматически) |
| `Сборка PT завершилась с кодом …` | Нет доступа к `gitlab.torproject.org` или к прокси модулей Go; повторите позже. Временно можно собрать без мостов: `-Paegis.buildPt=false` |
| В приложении «Нативное крипто-ядро не собрано» | В APK нет `libaegis_core.so` — см. [Шаг 5](#шаг-5-проверка-сборки) |
| «Встроенный Tor (Arti) не собран в этой сборке» | Ядро собрано без `tor` — см. ошибку в журнале сборки |
| «Адрес onion-релея не задан» | Вшейте адрес при сборке ([Шаг 3](#шаг-3-адрес-вашего-сервера)) или введите в **Настройки → Сеть и Tor** |
| Tor долго подключается или не подключается | Tor заблокирован в сети — включите мосты; встроенные строки мостов могли устареть — возьмите свежие на bridges.torproject.org |
| Сообщения не доходят | Собеседники на разных серверах; сервер недоступен (проверьте `docker compose ps` на сервере); на телефоне ограничена работа в фоне |
| Звонок не соединяется | На сервере не настроен TURN (`/v1/turn` отвечает 404) — README `aegis-server`, «TURN для звонков» |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Установленная версия подписана другим ключом — удалите её или используйте общий debug-ключ (раздел [«Подпись»](#подпись)) |
| Release-APK не устанавливается | Он неподписанный (`app-release-unsigned.apk`) — создайте `keystore.properties` |
| Gradle падает с `OutOfMemoryError` | Увеличьте `-Xmx` в `org.gradle.jvmargs` (`gradle.properties`) или закройте другие программы |
| Android Studio не видит `cargo`/`go`/`protoc` | Запустите её из терминала, где настроен `PATH`, или собирайте `./gradlew` в терминале |
